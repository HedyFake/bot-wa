## Kontrol yang ditelusuri

- **Syntax dan import.** Typecheck serta build lulus untuk konfigurasi TypeScript aktif. Pemeriksaan ini tidak meliputi paket opsional yang diimpor secara dinamis atau binary Linux.
- **Router dan alias.** Katalog simulasi mencakup 147 handler. Registri alias, cabang khusus di parser, dan katalog menu masih terpisah. Bentuk seperti .download dan .download ID memiliki target berbeda sesuai argumen. S06 menunjukkan konsekuensi urutan pencocokan.
- **Input dan kegagalan.** .calc menggunakan parser aritmetika di `src/modules/fun/fun-utility-service.ts:748`. Untuk .doc, .convert dan .ocr, input menuju pembuat dokumen, konversi unit atau buffer. Ekstraksi menggunakan stdin dan daftar argumen tetap di `src/modules/materials/extract.ts:5`. Dua ekstraksi dapat aktif sekaligus dan permintaan berikutnya ditolak saat sibuk. Uji beban, batas payload, symlink serta kehabisan ruang host masih terbuka.
- **Jaringan dan penanganan error.** Router AI menerapkan tenggat dan AbortController di `src/ai/model-router/router.ts:219`. Klien LMS memakai batas waktu di `src/modules/lms/client.ts:41`. Dispatcher mempunyai balasan kegagalan luar di `src/index.ts:152`. S08 tetap berlaku pada keseluruhan operasi.
- **Akses.** Jalur LMS mendahului AI. Kredensial opsional untuk login otomatis disegel dengan AES-GCM dan diikat ke identitas. Consent AI dibedakan dari izin LMS. Verifikasi ulang logout, pemakaian kunci dan retensi backup pada instalasi nyata masih diperlukan.
- **Grup dan recovery.** Ronde game diindeks per chat di `src/modules/fun/fun-utility-service.ts:1375`. Pengiriman broadcast meminta owner, item yang telah disetujui dan konfirmasi. Jeda antar pengiriman massal, retensi journald aktual, recovery reboot, restore dan idle 24 jam memerlukan uji VPS.
- **Kredensial lokal lainnya.** Inventaris merekam dua file lokal PostgreSQL dan parameter menyerupai kredensial pada arsip Akira. Simpan file tersebut di luar distribusi. [Inventaris kredensial](AUDIT.md#kredensial-yang-ditemukan)

## Urutan penanganan

Tangani S01 dan S02 bersama pemilik akun. Dahulukan S03–S05 dan uji penolakan sebelum membuka tool untuk data pribadi atau pemulihan. Perbaikan kode, migrasi, restore, instalasi dependensi dan deployment mengikuti persetujuan fase berikutnya.
